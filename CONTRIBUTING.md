# Contributing

## Layout

- `src/lib.rs`: the public API. `SCHEMA_VERSION` and `SchemaName` are written by hand.
- `src/generated.rs`: the lookup tables, which embed each bundled file with `include_str!`. It is generated by `cargo xtask codegen` and never edited by hand.
- `schemas/<version>/`: every bundled OATS release from 0.8.0 on, byte-identical to `schemas/` in the `v<version>` tag of [oatschema/oats](https://github.com/oatschema/oats), with a `MANIFEST.json` recording the tag, the commit and each file's SHA-256. Bundled files are never edited, and a bundled version is never rewritten.
- `xtask/`: maintainer tasks (`sync` and `codegen`). It is not published.
- `tests/`: integration tests. `tests/bundled.rs` checks the bundled files against their manifests and, when an oats checkout is available, against the release tags.

## Development

```
cargo test --workspace
cargo test --workspace --all-features
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo xtask codegen --check
cargo +1.85 test --workspace --all-features   # the minimum supported Rust version
cargo package --list                          # only src, tests, schemas, README, CHANGELOG, LICENSE, AUTHORS and Cargo files
```

`tests/bundled.rs` compares every bundled file with `git show v<version>:schemas/<file>` in an oats checkout. It uses `OATS_REPO` if set, failing if that isn't a git checkout, and otherwise `~/projects/oats`, skipping the comparison if that doesn't exist. CI clones oats and sets `OATS_REPO`, so the comparison always runs there.

## Bundling a new OATS release

Bundle a release only after oats has tagged and pushed it.

1. Fetch the tags into an oats checkout: `git -C ~/projects/oats fetch --tags origin`.
2. Run `cargo xtask sync ~/projects/oats vX.Y.Z`. The task:
   - reads the schemas from the tag's commit, never from the working tree;
   - refuses a tag that isn't on `origin` at the same commit;
   - refuses tags before `v0.8.0`, the first release this crate bundles;
   - checks every file:
     - a kebab-case name that isn't reserved (`changelog`, `docs`, `latest`);
     - UTF-8 JSON with no duplicate keys, whose top level is an object;
     - `$schema` is 2020-12, `$id` is `https://oatschema.org/<version>/<name>`, and `x-version` equals the tag;
     - no top-level `version` keyword (OATS renamed it to `x-version` in 0.8.0);
     - `x-license` has `id` `Apache-2.0` and a notice of the form `Copyright <year or year range> The OATS Authors`;
   - refuses to overwrite an existing version directory;
   - writes the files and `MANIFEST.json` to a staging directory and renames it into place, so a failed sync leaves nothing behind;
   - regenerates `src/generated.rs`.
3. Update `src/lib.rs`: set `SCHEMA_VERSION` to the new version and add a `SchemaName` variant, with its `as_str` spelling and an entry in `SchemaName::ALL`, for each new schema. The build fails until every bundled name has a variant.
4. Bump the crate's minor version (see "Versioning policy" in the README) and add a `CHANGELOG.md` entry.
5. Run the checks above.

The task follows the rules of `scripts/sync_schemas.py` in [oatschema-py](https://github.com/oatschema/oatschema-py) for releases from 0.8.0, adds the `x-license` check that oatschema-js also makes, and produces the same files and manifests.

## Licensing and sign-off

- Contributions are licensed under Apache-2.0, the licence the project is released under. There is no CLA.
- Contributors keep the copyright in their contributions; together they are The OATS Authors. Add yourself, or your employer, to [AUTHORS](AUTHORS) when you contribute.
- Every commit needs a [Developer Certificate of Origin](https://developercertificate.org/) sign-off: commit with `git commit -s`.
- Every new source file (`.rs`, `.toml`, `.yml`, `.gitignore`) starts with this header, in the file's comment syntax; the xtask tests check it, and `cargo xtask codegen` writes it into `src/generated.rs`:

  ```
  // SPDX-FileCopyrightText: 2026 The OATS Authors
  // SPDX-License-Identifier: Apache-2.0
  ```

  Bundled schema files are never edited, so they carry the notice in their own `x-license` keyword instead.

## Releasing

Releases are published by `.github/workflows/release.yml` when a `v<version>` tag is pushed. The workflow runs CI, checks that the tag matches the version in `Cargo.toml`, and publishes to crates.io with trusted publishing, so no API token is stored. Before tagging, set the version in `Cargo.toml`, date the `CHANGELOG.md` entry and run `cargo publish --dry-run`.
